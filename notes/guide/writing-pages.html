Writing pages

Each page is one HTML file. Its <h1> is the page's name in search and in the sidebar, and every <h2 id="..."> becomes a search entry of its own, so readers can jump straight to a section.

Sections

Give each section an <h2> with a short, unique id: lower case, words joined by hyphens. Use <h3> inside a section for smaller headings; those aren't search entries.

A smaller heading

Plain paragraphs, bold, italics and inline code all work.

Code

Put code in a <pre> and name its language in data-language, which colours it. Escape <, > and & as &lt;, &gt; and &amp;. Each block gets a copy button.

// Languages include javascript, typescript, html, css, bash, json, python and ruby.
const total = items.reduce((sum, item) => sum + item.price, 0);

Notes and warnings

A <blockquote> is shown as a highlighted note: good for tips and warnings.

Lists and tables

  • Lists are <ul> (bullets) or <ol> (numbered).
  • Tables are plain <table>s:
CommandWhat it does
git statusShows what changed
git log --onelineLists the commits

Links

Link to another page of the doc by its path relative to this one, without .html: Git basics, or a section of it: saving a checkpoint. Links to other websites work as usual: DevDocs.

Images

Use full addresses for images, e.g. <img src="https://…/diagram.png" alt="…">, and always describe them in alt.
